# ADR-015：API 治理企业化升级（P1）

- 状态：Proposed
- 日期：2026-03-13
- 决策者：Agent Powflow 核心开发组
- 关联：`ADR-010`、`ADR-011`、`ADR-014`

## 背景
当前系统已具备 API 池、用量统计、预算与告警、日志追踪等基础能力，但距离企业级运营闭环仍有差距：

1. 计费可信度不足：估算费用与供应商账单缺少对账闭环。
2. API Key 生命周期薄弱：缺少轮转、到期治理、灰度切换规范。
3. 告警运营能力不足：状态机与处理流程不完整，抑制与升级机制不足。
4. 控制台信息密度高但闭环弱：缺少“发现 -> 处置 -> 验证”单路径体验。

## 目标
构建面向企业运维与成本治理的 API 管理闭环，优先实现：

1. 成本可信：可解释、可复核、可对账。
2. 告警可运营：状态清晰、处理可追踪、噪声可抑制。
3. Key 可治理：安全存储、轮转规范、风险可控。
4. 控制台可执行：从指标到动作一跳到位。

## 现状评估（2026-03）
### 已具备
1. API 池治理：端点、默认路由、超时/重试/熔断、冻结。
2. 用量统计：按天、模型、任务、API 路径、KB、API Key 指纹等维度。
3. 预算告警：预算规则 + 告警列表 + 状态更新接口。
4. 观测能力：日志中心、风险事件、权限警告、Trace 跳转。

### 缺口
1. 价格版本化与账单对账能力缺失。
2. 告警状态机不统一（历史存在 OPEN/ACK/RESOLVED 之外的别名状态）。
3. Key 生命周期策略缺失（轮转窗口、到期告警、灰度切换）。
4. SLO 指标体系不完整（错误预算、恢复时长、可用率口径）。

## 决策
### 1) 统一告警状态机
平台预算告警统一为：

1. `OPEN`：新告警/触发中
2. `ACK`：已确认，继续观察
3. `MUTED`：静默，不再反复提醒
4. `RESOLVED`：已处置完成

说明：后续禁用模糊状态命名（如 `IGNORED`），避免状态语义分裂。

### 2) 成本可信化（P1）
新增“价格版本 + 生效时间”口径，所有费用按事件时间匹配价格版本。
后续增加账单导入与偏差报表（对账差异率、偏差来源）。

### 3) API Key 生命周期治理（P1）
确立最小闭环：

1. Key 永不回显，仅展示指纹与元数据。
2. 轮转流程：新 Key -> 灰度 -> 切主 -> 旧 Key 冻结/删除。
3. 到期阈值告警（7/3/1 天）与使用异常告警。

### 4) 控制台闭环改造（P1）
统一“治理面板 -> 告警中心 -> 日志追踪 -> 处置动作 -> 回写状态”路径，减少跨页跳转。

## 数据模型与接口规划
### 预算告警（现有增强）
1. `GET /api/v1/admin/usage/api-tokens/alerts`
2. `PATCH /api/v1/admin/usage/api-tokens/alerts/{alert_id}`

增强点：
1. `status` 支持 `OPEN|ACK|MUTED|RESOLVED`
2. 前端筛选与动作与后端一致。

### 后续新增（P1 后半）
1. `GET /api/v1/admin/usage/api-tokens/reconciliation/summary`
2. `POST /api/v1/admin/usage/api-tokens/reconciliation/import`
3. `GET /api/v1/admin/api-keys/lifecycle`
4. `POST /api/v1/admin/api-keys/{id}/rotate`

## 安全与合规要求
1. Key 仅加密存储 + 指纹展示。
2. 所有状态变更写入审计日志（操作者、时间、原因、trace_id）。
3. 告警静默需保留可恢复能力与操作留痕。

## 分阶段实施
### P1-A（本次先行）
1. 告警状态机扩展到 `MUTED`。
2. 控制台告警筛选与操作改为 `ACK/MUTED/RESOLVED`。
3. 去除历史不一致状态入口。

### P1-B
1. 价格版本化与对账预览。
2. Key 生命周期元数据与轮转接口。

### P1-C
1. 告警抑制窗口、升级策略、通知通道。
2. SLO 指标面板补全。

## 验收标准
1. 告警状态流转可达 `OPEN -> ACK/MUTED -> RESOLVED`，前后端一致。
2. 控制台无无效状态提交（不再出现前端状态被后端拒绝）。
3. 审计日志可追踪告警状态变更操作。
4. P1-B/P1-C 完成后，成本偏差、Key 轮转、告警噪声具备可观测指标。
