# ADR-009：Chat 记忆融合策略（Memory Fusion Strategy）

- 状态：Accepted
- 日期：2026-03-03
- 决策者：Agent Powflow 核心开发组
- 关联：`ADR-005`、`ADR-007`、`ADR-008`

## 背景
随着对话长度增长，单一“最近窗口”策略会出现三类问题：

1. 召回不足：早期关键事实容易被截断丢失。
2. 成本失控：直接扩大上下文窗口会显著增加 token 开销。
3. 精度下降：不同来源信息混杂，缺少冲突消解与优先级机制。

需要一套可解释、可控成本、可迭代优化的混合记忆方案。

## 决策
采用“多策略融合 + 统一重排 + 预算注入”的记忆架构，核心由六层信息源组成：

1. 固定最近对话窗口（L0）
2. 长对话异步总结（L1）
3. 关键数据记忆（L2，规则打分入库）
4. 用户画像 + 最近活动（L3）
5. 早期对话 RAG 检索（L4）
6. 关键词上下文提取（L5）

并引入三类控制组件：

1. 融合重排器（Fusion Ranker）
2. Token 预算分配器（Budget Manager）
3. 冲突消解器（Conflict Resolver）

## 架构说明
### L0 固定最近窗口
- 目标：保证局部连贯性与最低时延。
- 特点：不依赖额外模型调用，在线实时可用。

### L1 异步会话总结
- 目标：压缩中长对话历史，减少全量历史注入。
- 触发：达到消息数阈值、上下文预算阈值、主题切换。
- 输出：结构化摘要（目标/约束/偏好/决策/待办/未决问题）。

### L2 关键数据记忆
- 目标：沉淀高复用事实，避免仅靠窗口记忆。
- 策略：规则分在线筛选，后续支持异步 LLM 重排回写 `importance_v2`。

### L3 用户画像与最近活动
- 用户画像：长期稳定偏好（格式、语气、领域关注）。
- 最近活动：短期行为线索（近期主题、最近任务），设置 TTL 防污染。

### L4 早期对话 RAG
- 目标：召回早期历史中与当前问题语义相关的片段。
- 机制：query rewrite 后检索，降低语义漂移。

### L5 关键词上下文提取
- 目标：弥补向量检索漏召回（编号、专有词、缩写等）。
- 作为补偿通道，与 L4 合并后统一重排。

## 融合与注入规则
### 融合重排（统一候选池）
综合评分建议：

`score = w_rel * relevance + w_imp * importance + w_rec * recency + w_conf * confidence`

- `relevance`：与当前 query 的匹配度
- `importance`：记忆重要性分数
- `recency`：时间新近性
- `confidence`：来源可靠度（总结/用户确认/系统抽取）

### 预算分配（可配置）
默认建议：

- L0 最近窗口：30%
- L1 会话总结：25%
- L2 关键记忆：20%
- L4 历史 RAG：20%
- L3 用户画像：5%

超预算时按边际贡献裁剪，不允许整体超配。

### 冲突消解
- 同类槽位冲突时优先“新 + 高置信”版本。
- 保留历史版本与来源链，确保可审计可回溯。

## 数据与接口影响
### 数据层
- 现有记忆表保留，扩展字段：
  - `source_type`
  - `confidence`
  - `ttl_at`
  - `importance_v2`（可选）
  - `version`

### 接口层（规划）
- 记忆配置管理：开启/关闭各层策略与预算参数。
- 记忆观测接口：各层召回数量、命中来源、注入 token 消耗。
- 记忆重排任务接口：异步重算与重试。

## 预期收益
1. 记忆命中率提升（尤其是长对话下早期事实召回）。
2. token 成本可控（预算化 + 异步化）。
3. 行为可解释（来源、评分、冲突处理可追踪）。

## 代价与风险
1. 系统复杂度提升（多层召回 + 融合逻辑）。
2. 参数治理成本上升（需持续调优权重与阈值）。
3. 异步链路失败需明确降级（回退到 L0+L1）。

## 验收标准
1. 对话长度 > 100 轮时，关键约束信息召回率显著高于仅窗口策略。
2. 平均 token 开销在目标预算内稳定可控。
3. debug-web 可看到各层召回与注入统计。
4. 冲突记忆具备明确主版本与历史版本追踪。

## 实施阶段
1. P1：L0/L1/L2 + 预算注入（最小可用）
2. P2：L3/L4/L5 + 融合重排
3. P3：异步 LLM 重排、自动调参与质量评测

## 落地进展（2026-03-03）
以下为当前代码实现与 ADR 目标的对齐状态（用于阶段验收，不改变本 ADR 决策本身）：

### 已落地
1. L0 最近窗口：已实现，并按预算做窗口裁剪。
2. L1 长对话压缩：已实现 short/long summary，按消息阈值触发。
3. L2 关键记忆项：已实现入库与淘汰；支持 `importance`，并接入 `importance_v2` 回写能力。
4. L3 用户画像与最近活动：
   - 画像改为 LLM 自由侧写（非固定模板字段）。
   - 触发改为“新增用户消息阈值”而非时间间隔。
   - 采样改为增量游标（`last_profile_message_at`），避免重复全量采样。
   - 最近活动拆分为“主题信号（topic_signal）/事件信号（event_signal）”。
5. L4 会话历史 RAG：已实现会话片段检索（关键词 + 向量融合），默认仅会话内召回，避免跨会话串扰。
6. L5 关键词补偿：已实现会话片段关键词补偿检索并注入 prompt。
7. 融合观测：`chat_memory_fusion_logs` 已落地，记录 layer/budget/top_items。
8. 会话标题稳定化：已实现“最多顺延 5 次 + stable 判定 + 强制兜底”，并支持流式实时更新标题。

### 已偏离/调整点（相对原计划）
1. L4 召回范围从“可跨会话”收敛为“默认仅当前会话”：
   - 原因：降低错误召回与上下文污染风险。
   - 结论：跨会话召回作为后续可配置增强项，而非默认行为。
2. L3 画像触发从“时间驱动”改为“新增消息驱动”：
   - 原因：更贴合低活跃用户与 token 成本控制。

### 尚未完成（进入后续阶段）
1. 分层预算管理器完整版：已实现基础比例裁剪，尚未形成可评估的“边际贡献裁剪”闭环。
2. 质量评测与自动调参（P3）：尚未落地离线评测指标与自动调权机制。

### 新增落地（2026-03-03，第二次更新）
1. Conflict Resolver 已落地（会话级）：
   - 规则：按 `kind + 规范化文本签名` 归组，保留最新项为 `active`，旧重复项标记 `conflict_shadow`；
   - 追踪：阴影项记录 `shadowed_by_item_id`，保留可审计链路；
   - 注入侧：prompt 注入与 rerank 默认仅使用 `active` 项，减少重复噪声。
2. 记忆重排任务已后台化：
   - `POST /api/v1/admin/chat/memory/rerank` 改为异步入队，返回 `job_id`；
   - 新增任务查询接口：
     - `GET /api/v1/admin/chat/memory/rerank/jobs`
     - `GET /api/v1/admin/chat/memory/rerank/jobs/{job_id}`
   - chat-plane API 启动后运行后台 worker 消费队列，完成后回写 `importance_v2/confidence`。
3. 幂等与防重：
   - 同一 `session_id` 存在 `PENDING/RUNNING` 任务时进行去重返回，避免重复重排。

### 当前建议的阶段状态
- 当前阶段定义为：`P2-增强版（可灰度）`
- 进入下一阶段条件：
  1. 建立评测基线并跑首轮参数校准；
  2. 完成边际贡献裁剪闭环；
  3. 补齐批量重排重试/优先级治理策略。
