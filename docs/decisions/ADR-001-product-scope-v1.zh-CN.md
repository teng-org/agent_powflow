# ADR-001：产品范围与架构基线（v1）

- 状态：Accepted
- 日期：2026-02-09
- 决策方：产品 + 架构
- 适用范围：`agent_powflow` v1 企业优先基线

## 背景（Context）

本项目目标是构建一个前后端分离的个人/团队知识库 + Agent 系统，核心形态为：

- Vue 前端（`web-app` + `web-admin`）
- Spring Boot 控制平面（用户、租户、治理、权威状态）
- Python 执行平面（AI 流水线与运行时）
- 多租户隔离、任务编排、状态同步、可插拔扩展
- Agent Canvas 用于可视化管理，但以可执行 DSL 为唯一真相

为避免 MVP 过度设计，同时保留企业可落地能力，需要明确产品边界与技术取舍。

## 决策（Decision）

1. 用户优先级：企业优先，个人用户作为试用/自部署入口。
2. 私有化部署：v1 支持私有化，但 MVP 不强制完整 air-gapped 离线。
3. 合规策略：先实现合规能力，不将正式合规认证纳入 MVP。
4. 多租户隔离：MVP 采用 L1 逻辑隔离（全链路强制 `tenant_id`）。
5. 模型策略：架构支持双栈，MVP 先落地 OpenAI 兼容模型提供方。
6. 向量库：Qdrant 作为默认生产选型。
7. 消息中间件：RabbitMQ 作为默认生产选型。
8. 规模假设：MVP 面向中小企业规模，不按互联网超高并发设计。
9. Canvas 范围：MVP 仅支持 DAG 工作流，不引入循环/人工节点/复杂状态机。
10. 商业化：v1 落地最小 License 边界（能力授权），不做复杂计费引擎。

## 影响（Consequences）

### 正向影响

- 在控制复杂度的同时，保留企业化演进路径。
- 通过 Qdrant + RabbitMQ 降低运维复杂度并提升工程确定性。
- 通过 DSL-first 保障 Agent 能力迁移与版本可追溯。
- 通过最小 License 机制提前验证商业可行性。

### 代价与权衡

- 部分客户仍可能要求严格离线与正式合规认证。
- OpenAI-first 在本地模型补齐前存在外部依赖风险。
- L1 逻辑隔离可满足 MVP，但不适用于强隔离客户。

### 后续动作

- 在 post-MVP 规划中引入 L2/L3 多租户隔离方案。
- 当客户需求或成本触发时补齐本地模型路径（如 vLLM/Ollama）。
- 在目标行业明确后，从“合规能力”升级到“认证就绪”。
- 继续补充 ADR：向量库细化、队列拓扑、DSL 版本治理、License 机制细节。
