# ADR-002：前后台域划分与 Canvas 执行边界（v1）

- 状态：Accepted
- 日期：2026-02-09
- 决策方：产品 + 架构
- 适用范围：`agent_powflow` v1
- 关联：
  - `docs/requirements/product-scope-clarification-v1.zh-CN.md`
  - `docs/requirements/product-vision-v2.md`

## 背景（Context）

随着产品范围进一步明确，系统已形成“前台对话页 + 多后台分治 + Canvas 编排 + 执行层落地”的结构。  
若不提前固化边界，后续开发容易出现：

- 前后台职责混淆（功能重复或缺位）
- Canvas 与运行时耦合（迁移困难）
- 配置与执行逻辑混写（难治理、难升级）

因此需要 ADR 固化前后台域边界与 Canvas 执行边界。

## 决策（Decision）

1. 面向客户的前台仅保留对话与结果展示能力，不承载系统治理能力。
2. 后台拆分为三个域：
   - 运维与系统管理后台
   - AI 能力配置后台
   - 资源设施后台（模块库/知识库/工具库）
3. Agent Canvas 是“编排与管理界面”，不是运行时真相。
4. 运行时唯一真相为 Workflow DSL + 版本快照，Canvas layout 仅用于可视化。
5. Canvas 对输入进行引流与数据流编排，具体执行由 Python 执行层生效。
6. Spring Boot Control Plane 负责权威状态、治理、API 对外能力，不直接承载 AI 推理执行。
7. 后续多端扩展统一走 Control Plane API，保持资源模型与权限模型一致。

## 边界定义（Boundary）

### 前台（Web Chat）

- 输入：文本/图片/音频/文件（是否开放由 AI 配置后台控制）
- 输出：回答、引用、任务进度、错误提示
- 不承担：租户治理、系统策略配置、模型与工具注册

### 运维与系统管理后台

- 用户/租户/RBAC
- 系统配置、审计日志、运行统计
- 任务监控、失败重试、成本视图

### AI 能力配置后台

- 控制前台开放能力开关（多模态/工具）
- 模型、检索、提示词、限额策略
- 按租户/应用发布与回滚 AI 配置

### 资源设施后台

- 模块库（Canvas 节点能力）
- 知识库（KB/文档/索引）
- 工具库（Tool 注册、版本、权限）

### 控制平面（Spring Boot）

- 权威状态：Task/Run/Config/License/Audit
- 治理策略：鉴权、配额、策略校验、版本控制
- 对外 API：面向 Web/移动端/第三方系统

### 执行平面（Python）

- 读取 DSL 版本快照并执行
- 调度解析、检索、工具、模型节点
- 回传任务与运行事件，不直接定义业务治理规则

## 影响（Consequences）

### 正向影响

- 结构稳定：前台、后台、控制/执行平面职责清晰。
- 可迁移：Canvas 不绑定运行时，DSL 可跨环境迁移。
- 可演进：后台能力可独立迭代，不影响前台对话体验。
- 可扩展：Control Plane 可平滑扩展多端接入。

### 代价与约束

- 需要更严格的接口契约管理（Canvas -> DSL -> Runtime）。
- 需要额外建设后台域间协作规范（配置发布、权限联动）。

## 实施约束（Guardrails）

1. 禁止在 Canvas layout 中存储执行语义。
2. 禁止前台直接修改运行时 DSL 定义。
3. 所有执行事件必须回传并关联 `tenant_id/task_id/run_id/trace_id`。
4. 配置发布必须版本化、可回滚、可审计。
5. 新增前端入口（移动端/第三方）必须复用 Control Plane 鉴权与资源模型。
