## 1. 文档目的

本文只描述当前仍缺少或仅部分完成的企业级能力。每项需求严格按以下四点对应说明：

1. **功能需求**：企业用户需要什么，以及当前缺口是什么；
2. **使用场景例子**：以真实组织、操作者和故障/业务过程说明如何使用；
3. **功能作用**：该能力解决的风险、效率或合规问题；
4. **功能实现**：建议的系统边界、数据契约、实施路径和验收条件。

已完成的 Control Task Authority、事务 Outbox、租约/主动取消、基础人工审批、死信重放、跨存储修复、MinIO 版本化与容量准入、四存储隔离恢复、Provider 安全契约执行器等不作为“缺失功能”重复立项；本文在这些基线上定义企业化增量。

## 4. 详细企业级需求

### ENT-01 多节点高可用与自动故障切换

- 优先级：P0
- 当前状态：单机 Compose 和单节点故障恢复机制已验证；尚无完整生产集群拓扑、自动选主和节点级 SLA 证据。

1. **功能需求**

   PostgreSQL、MongoDB、RabbitMQ、Qdrant、MinIO、Control、Execution、Chat 和 Worker 均应支持冗余实例，任一应用实例或单个基础设施节点故障时，系统自动摘除故障节点并继续提供受约束服务。不得依赖人工重启或单机本地 volume 才能恢复。

2. **使用场景例子**

   工作日高峰期一台 Worker 主机宕机。正在运行的文档入库和 Workflow 任务由租约超时机制重新领取，已完成副作用不重复执行；API 流量自动转移到其他实例，用户可以查询原 Run 的权威状态，而不是得到永久 `RUNNING`。

3. **功能作用**

   消除单点故障，支撑企业 SLA；验证现有 Outbox、租约、幂等、修复账本在多实例竞争下仍成立；把“进程恢复能力”升级为“节点故障业务连续性”。

4. **功能实现**

   - PostgreSQL 使用托管 HA 或 Patroni/云原生主从，业务连接通过代理或服务发现切换；MongoDB 使用副本集；RabbitMQ 使用 quorum queue；Qdrant 使用多副本 collection；MinIO 使用多节点纠删码。
   - Control/Execution/Chat 保持无状态或只依赖共享权威存储；Worker 使用独立队列消费者身份、心跳、可见租约和 fencing token。
   - 增加 Pod/实例级 readiness、liveness、优雅下线和最大不可用实例约束。
   - 验收必须覆盖杀死主库/Worker/API/对象节点、网络分区、恢复重平衡、重复消息和进行中任务；证明终态唯一、无跨租户串扰、无重复副作用，并形成 RTO 记录。

### ENT-02 持续容量、弹性扩缩容、背压与降级

- 优先级：P0
- 当前状态：逻辑配额、容量预留、MinIO 物理指标、有界压力及隔离磁盘满恢复已完成；尚缺长时间生产拓扑压力和系统级降级策略。

1. **功能需求**

   系统应按 API、队列、Worker、Provider、数据库和对象存储维度定义容量模型，支持水平扩缩容、租户公平调度、流量整形、背压、熔断和明确的降级响应。容量耗尽时不得无限排队、拖垮全部租户或返回不可解释错误。

2. **使用场景例子**

   某租户一次上传 5,000 份文档，同时另一个租户运行实时 Chat。系统对批量入库实施租户并发上限和队列权重，Chat 保持低延迟；当对象存储接近阈值时，新的上传返回结构化 507，而查询和已发布知识库检索继续可用。

3. **功能作用**

   防止噪声邻居和级联故障；使容量规划、套餐销售和 SLA 具备数据依据；在资源不足时优先保护读取、控制面和高优先级业务。

4. **功能实现**

   - 为每个消费点定义请求率、并发、队列深度、等待时间、内存、存储和 Provider token/cost 预算。
   - 引入租户级 token bucket/加权公平队列、Worker autoscaling 指标、全局最大在途任务和任务 admission control。
   - 定义降级矩阵：禁新上传、延迟低优先级摘要、关闭非关键重排、只读模式、重试建议和 `Retry-After`。
   - 验收至少执行 4–24 小时持续饱和、生命周期扫描、Provider 429、数据库连接耗尽、多节点降级；记录 P50/P95/P99、错误率、队列恢复时间、告警提前量和资源泄漏。

### ENT-03 跨存储恢复点、PITR 与异地不可变灾备

- 优先级：P0
- 当前状态：PostgreSQL/MongoDB/Qdrant/MinIO 分项隔离恢复及统一 backup set 已验证；当前 backup set 是在线模糊时间窗，不是跨存储原子恢复点。

1. **功能需求**

   企业应能把 PostgreSQL、MongoDB、Qdrant、MinIO 和消息积压恢复到一个可解释的业务恢复点，支持 PostgreSQL 时间点恢复、异地加密副本、不可变保留、定期演练以及恢复后自动对账。

2. **使用场景例子**

   管理员误删除一个租户知识库，30 分钟后发现。运维选择事故前 5 分钟的恢复点，在隔离环境恢复权威元数据、对象版本和向量快照，生成影响清单，经审批后执行租户级恢复，而不是覆盖整个生产环境。

3. **功能作用**

   将“备份文件存在”升级为“可以按业务时间点恢复”；降低勒索、误删、区域故障和跨存储不一致风险；提供可审计的 RPO/RTO 证据。

4. **功能实现**

   - PostgreSQL 开启 WAL archive/PITR；MongoDB 采用带 oplog 的一致性备份；Qdrant/MinIO 生成带时间与版本清单的快照。
   - Control 建立 `backup_set`/`checkpoint` 权威记录：写入静默开始、各存储游标、完成时间、校验和、加密/保留状态和恢复验证结果。
   - 备份使用 KMS 信封加密，复制到跨账号/跨区域、Object Lock/WORM 介质；保留策略和删除需要双人审批。
   - 恢复工具默认只恢复到隔离目标，执行 schema/version 兼容检查、跨存储修复 dry-run、租户边界核对后才允许切换；按季度演练并验收 RPO/RTO。

### ENT-04 Vault/KMS、生产 PKI 与服务身份生命周期

- 优先级：P0
- 当前状态：生产 Secret fail-closed、强度/复用校验、泄漏扫描、JWT/Fernet 轮换和 MinIO 私有 CA 已完成；Secret 仍主要由环境变量和静态内部 token 提供。

1. **功能需求**

   所有数据库、消息、对象存储、Provider、Webhook、JWT、Workflow 加密密钥和服务证书必须由集中式 Secret/KMS/PKI 管理，支持短期凭据、自动轮换、吊销、使用审计和故障降级。

2. **使用场景例子**

   一名运维人员离职，其曾接触的 Provider Key 需要立即轮换。平台在不中断任务的情况下把新 Key 标记为主用，旧 Key 进入短暂双读窗口；使用旧 Key 的实例产生告警，窗口结束后集中吊销。

3. **功能作用**

   减少长期明文 Secret、人工分发和泄漏扩散；满足密钥轮换、职责分离和访问审计要求；降低证书过期导致全站故障的风险。

4. **功能实现**

   - 接入 Vault、云 KMS/Secret Manager 或等价服务；工作负载通过机器身份领取短期凭据，不把 root/key 写入镜像、仓库或长期 env 文件。
   - Workflow 内容密钥采用 KMS 信封加密；JWT 使用可轮换非对称密钥和 JWKS；服务间逐步由静态 token 迁移到 mTLS + workload identity。
   - 建立 Secret 版本、年龄、到期、最后使用、旧 slot 使用率、轮换任务和吊销事件指标。
   - 验收覆盖主密钥不可用、轮换中断、旧实例、证书双发/切换、吊销和灾备恢复；日志与报告不得输出 Secret 值。

### ENT-05 企业身份联邦、MFA、SCIM 与细粒度授权

- 优先级：P0
- 当前状态：已有租户、用户、角色、JWT/refresh 和基础 RBAC；尚缺企业 IdP 联邦、自动人员生命周期和资源级授权治理。

1. **功能需求**

   支持 OIDC/SAML SSO、MFA、SCIM 用户/组织同步、企业域绑定、会话策略、条件访问，以及租户/项目/知识库/Workflow/审批范围的细粒度角色与权限。

2. **使用场景例子**

   某企业通过 Entra ID 登录。员工加入“法务知识库管理员”组后自动获得指定空间的维护权限；员工离职时 SCIM 禁用账号、撤销所有 refresh token 和活动会话，但保留其审计记录。

3. **功能作用**

   避免企业重复维护账号；确保入职、调岗、离职权限及时一致；支撑最小权限、职责分离和高风险操作二次认证。

4. **功能实现**

   - 建立 `identity_provider`、域验证、外部 subject/group 映射、SCIM 同步游标与幂等事件模型。
   - 权限从粗粒度角色演进为 `subject + action + resource scope + condition`，重要资源使用显式授权或策略引擎。
   - 高风险操作要求 step-up MFA；提供会话列表、设备/位置风险、全局撤销和紧急 break-glass 账号审计。
   - 验收覆盖 JIT/SCIM 创建、组变更、离职撤销、多租户同邮箱隔离、IdP 证书轮换、时钟偏差和 IdP 暂时不可用。

### ENT-06 数据面隔离、最小权限与数据驻留

- 优先级：P0
- 当前状态：应用层 tenant-aware 校验和部分存储前缀隔离已实现；三平面仍共用 PostgreSQL `public` schema，生产最小权限和驻留策略未闭环。

1. **功能需求**

   Control、Execution、Chat 应使用独立 schema/数据库角色和最小权限连接；租户数据在关系库、对象存储、向量库、日志、备份中具有一致隔离边界，并可配置区域驻留和专属资源。

2. **使用场景例子**

   金融租户要求数据只保存在中国区域并使用专属加密密钥；普通租户使用共享集群。即使 Execution 凭据泄漏，也不能读取 Control 的 refresh token、审批审计或其他租户对象。

3. **功能作用**

   减少单个服务凭据被攻破后的横向影响；满足数据驻留、专属密钥和高隔离租户要求；使数据库权限成为应用校验之外的第二道边界。

4. **功能实现**

   - 分阶段把三平面对象迁入独立 schema/数据库，拆分 migration owner 与 runtime role；默认撤销 `public` CREATE 和跨 schema 访问。
   - 对象 key、Qdrant collection/payload、Mongo collection 和备份 manifest 强制携带 tenant/region；必要时引入 RLS 或物理专属实例。
   - 建立 tenant data placement、KMS key、保留策略和迁移任务，跨区域移动必须审批并留审计。
   - 验收使用错误服务账号、错误 tenant、备份恢复和跨区域迁移执行负向测试，证明数据库层和存储层都拒绝越权。

### ENT-07 SLO、分布式追踪与外部值班闭环

- 优先级：P0
- 当前状态：已有结构化日志、部分 Prometheus 指标、MinIO Alertmanager 和业务告警事实；尚无全链路 trace、统一 SLO/错误预算和正式值班渠道。

1. **功能需求**

   为 Chat、Workflow、文档入库、审批、Provider、队列和存储定义可观测黄金信号、SLO、错误预算、分布式追踪、告警路由和事件响应流程。

2. **使用场景例子**

   Chat P95 首 token 延迟连续 10 分钟超标。告警自动关联受影响租户、Provider endpoint、Run/trace ID、最近发布版本和熔断状态，通知值班平台；值班人员从 Console 跳转到完整跨服务链路，而不是逐容器搜索日志。

3. **功能作用**

   缩短发现和定位时间；把“服务 running”转化为用户体验与业务结果指标；用错误预算约束发布节奏和容量投资。

4. **功能实现**

   - 统一 OpenTelemetry trace/span、request/run/task/tenant correlation ID 和脱敏 baggage；贯通 HTTP、SSE、RabbitMQ/Celery、数据库和 Provider 调用。
   - 定义 SLI：可用率、首 token、Run 完成率、队列等待、审批超时、检索延迟、跨存储修复年龄和成本偏差。
   - 告警进入 PagerDuty/飞书/钉钉/Teams/Slack 等正式渠道，支持去重、抑制、升级、确认、自动恢复和 runbook 链接。
   - 验收通过故障注入证明告警在目标时间内触发/恢复、trace 完整、敏感数据不泄漏，并执行值班演练和复盘。

### ENT-08 真实模型供应商验收与成本对账

- 优先级：P0
- 当前状态：安全付费门禁、脱敏报告、本地真实网络故障沙箱和严格熔断状态机已完成；尚未获得真实商业账号调用与账单核对证据。

1. **功能需求**

   对每个正式 LLM/Embedding 供应商建立上线合同：认证、模型能力、流式格式、usage、限流头、请求 ID、错误分类、价格、数据使用条款、区域和故障切换均需验证。

2. **使用场景例子**

   主 Provider 在某区域持续 429。路由器根据任务类型、租户数据策略、成本预算和健康状态切换到已批准的备用模型；事后平台能用供应商 request ID 对账，并解释本次切换带来的价格和质量变化。

3. **功能作用**

   防止“OpenAI-compatible”名义兼容但细节不一致；控制不可预期费用；确保故障切换不会违反租户区域、隐私或模型准入政策。

4. **功能实现**

   - 使用 `tools/provider_contract.py` 在专用低额度账号执行 Chat/Embedding 契约，报告只保留协议证据和费用，不落正文、向量或密钥。
   - 建立供应商/模型注册表：版本、能力、区域、价格生效期、数据政策、最大上下文、限流和已批准任务。
   - 对接供应商账单或用量导出，按 request ID/模型/租户做日对账，偏差进入告警和人工处置。
   - 验收覆盖正常、401、429、5xx、超时、流中断、usage 缺失、价格变更、熔断半开和备用切换；任何付费测试必须显式授权和费用上限。

### ENT-09 高级人工审批协作

- 优先级：P1
- 当前状态：持久暂停/恢复、角色审批、超时决定、SLA、保留事实和可靠 Webhook 已完成；缺少多人协作和复杂治理。

1. **功能需求**

   审批节点应支持委派、转交、加签、多人会签/或签、撤回、评论、附件、替代审批人、节假日日历、分级升级、利益冲突和长期不可变归档。

2. **使用场景例子**

   合同生成 Workflow 要求法务与财务会签。财务审批人休假时按组织规则自动委派；法务上传修改附件并评论，发起人撤回修订后重新提交；超时先提醒，随后升级到部门负责人。

3. **功能作用**

   让审批从单人“同意/拒绝”升级为真实企业流程；减少线下沟通和审批失联；形成责任、证据和时限完整的合规链路。

4. **功能实现**

   - 扩展 approval definition/instance/participant/action/comment/attachment/delegation/escalation 表，动作使用乐观锁和幂等键。
   - DSL 定义审批策略：`all/any/quorum/sequential`、动态参与人表达式、替代规则、SLA 日历和超时动作。
   - 附件进入版本化对象存储，带病毒扫描、大小/类型限制、内容哈希和访问审计；长期记录进入 WORM 归档。
   - 验收覆盖并发审批、重复点击、委派循环、人员离职、附件失败、撤回/重提、超时与 Run 删除后审计保留。

### ENT-10 跨 Worker/嵌套并行与补偿执行

- 优先级：P1
- 当前状态：当前 `parallel.fork/join` 支持单进程内 2–8 分支、确定性合并和失败/取消；尚未支持跨 Worker 持久化分支和嵌套图。

1. **功能需求**

   Workflow 应支持跨 Worker 分支调度、嵌套并行、动态 fan-out、部分成功策略、分支级重试/取消、补偿事务和进程重启后的确定性恢复。

2. **使用场景例子**

   一个尽调 Workflow 为 300 家公司并行检索、摘要和风险评分。分支分布到多个 Worker；10 家外部接口失败时，根据策略保留 290 家结果并生成失败清单，操作者只重试失败分支，而不是重跑全部任务。

3. **功能作用**

   支撑大规模批处理和长流程；提高资源利用率；避免单 Worker 内存/进程成为瓶颈；为部分成功和可恢复补偿提供权威语义。

4. **功能实现**

   - Control 持久化 branch instance、依赖计数、join barrier、branch attempt、输出引用和补偿状态；每个分支拥有稳定幂等身份。
   - Execution 将分支作为独立消息投递，使用租约/fencing 防止旧 Worker 回写；大输出存对象存储，仅在状态中保存引用和 checksum。
   - DSL 定义 `fail_fast / collect_errors / min_success / quorum`、最大并行、嵌套深度、超时和 compensation 节点。
   - 验收覆盖 Worker 中途死亡、重复投递、乱序完成、嵌套取消、部分成功、join 重放和补偿失败，证明结果确定且审计单调。

### ENT-11 企业触发器、调度与事件接入

- 优先级：P1
- 当前状态：已有人工/API 发起和内部 Outbox；尚无完整 Cron、Webhook、消息事件和文件到达触发治理。

1. **功能需求**

   Workflow 应支持时区感知的 Cron、一次性计划、签名 Webhook、消息主题、对象到达和业务事件触发，并提供暂停、补跑、错过策略、去重和触发审计。

2. **使用场景例子**

   每个工作日 08:00 自动汇总前一日客服记录；上游 CRM 通过签名 Webhook 触发客户风险分析；系统停机两小时后按策略只补跑一次，而不是把所有错过时间点同时执行。

3. **功能作用**

   把平台从手工执行工具升级为企业自动化平台；减少外部脚本；统一入口安全、幂等、排期和运行审计。

4. **功能实现**

   - Control 增加 trigger definition、next fire time、delivery/dedup ledger 和 trigger-run 关联；调度领取使用数据库锁或专用调度器。
   - Webhook 支持 HMAC/mTLS、时间戳防重放、IP/host 策略、schema 校验和 secret 引用；事件总线使用明确 topic/consumer contract。
   - 定义 misfire：跳过、立即一次、逐次补跑；支持时区、DST、黑名单日期、并发策略和每租户限额。
   - 验收覆盖双实例调度、时钟偏差、DST、重复 Webhook、签名错误、停机补跑、禁用/恢复和版本固定。

### ENT-12 长连接断线续传与客户端恢复

- 优先级：P1
- 当前状态：Chat/Run SSE、主动取消、断线取消、历史事件查询和终态约束已实现；尚无标准 cursor/`Last-Event-ID` 续传。

1. **功能需求**

   浏览器、移动端和代理层断线后应能用稳定事件游标恢复 Chat、Run 和 Task 流，不重复展示 token/事件，也不因短暂网络波动自动取消服务端长任务。

2. **使用场景例子**

   用户在移动网络中生成长报告，连接中断 20 秒。客户端重连并携带最后事件 ID，服务端补发缺失事件后继续实时推送；若 Run 已结束则返回完整终态和结果引用。

3. **功能作用**

   提升弱网和企业代理环境下可靠性；减少重复模型调用和费用；让长任务体验与服务端权威状态一致。

4. **功能实现**

   - 所有流事件使用 Run 内单调 sequence/event ID 并持久化；SSE 接受 `Last-Event-ID` 或 cursor，先补历史再切换实时订阅。
   - 区分“连接丢失”和“用户取消”；采用有限 detach grace period，显式取消仍立即触发当前主动中断契约。
   - 客户端建立去重 reducer、指数重连、连接状态、终态校验和超时回退查询。
   - 验收覆盖代理缓冲、重复/乱序连接、历史截断、多标签页、服务重启、Run 已终态和跨租户 cursor 伪造。

### ENT-13 合规审计、数据保留、法律保全与 DLP

- 优先级：P1
- 当前状态：已有业务审计、审批保留、版本化对象和部分脱敏；尚无统一保留策略、法律保全、不可变审计链和敏感数据治理。

1. **功能需求**

   企业管理员应能配置数据分类、保留/删除期限、法律保全、不可变审计、导出审批、敏感信息检测/脱敏和数据主体删除，同时保持审计与业务数据的合法边界。

2. **使用场景例子**

   法务要求某项目全部 Run、审批、输入附件和输出保留七年并禁止删除；另一名用户提出删除请求，系统删除其可删除内容，但对受法律保全的数据只做访问限制并记录拒绝原因。

3. **功能作用**

   支撑监管、诉讼保全、隐私请求和内部审计；避免“业务删除即审计消失”或“无限保留所有敏感数据”两种风险。

4. **功能实现**

   - 建立 data classification、retention policy、legal hold、deletion job、export request 和 disposition audit 模型。
   - 审计事件使用 append-only/WORM 存储、哈希链或签名批次；导出文件带 manifest、checksum、操作者和审批事实。
   - 文档/Prompt/日志进入可配置 DLP/PII 检测，支持阻断、脱敏、标记、加密和受控例外；模型发送前执行租户策略。
   - 验收覆盖保留到期、hold 冲突、租户删除、备份中的删除标记、审计防篡改、导出越权和敏感字段不进入日志。

### ENT-14 租户套餐、配额例外、成本分摊与计费治理

- 优先级：P1
- 当前状态：已有租户逻辑容量、API/模型用量、价格版本、预算和告警；尚未形成统一产品套餐、例外审批和财务级分摊。

1. **功能需求**

   平台应按租户/部门/项目提供套餐、资源配额、并发、模型白名单、预算、超额策略、成本中心、内部 showback/chargeback 和调额审批。

2. **使用场景例子**

   研发部门使用高级模型月预算 10 万元，客服部门只允许低成本模型。研发临时申请两周并发扩容，经审批后自动生效和到期回收；月末财务按成本中心导出可对账明细。

3. **功能作用**

   控制平台成本和资源争抢；把技术配额转化为企业产品能力；为预算负责人提供预测、归因和异常发现。

4. **功能实现**

   - 建立 plan、entitlement、quota override、effective period、cost center 和 approval reference；所有计算按版本和生效时间可追溯。
   - Admission control 统一读取 entitlement，覆盖存储、请求、并发、任务、token、模型、保留期和导出能力。
   - 用量账本使用幂等 usage event，支持供应商账单对账、币种/税率、价格版本和成本分摊维度。
   - 验收覆盖并发超限、预算软/硬限制、调额生效/过期、补记用量、价格回溯和跨租户财务导出隔离。

### ENT-15 企业 Console 质量、无障碍与端到端验收

- 优先级：P1
- 当前状态：统一 Console 已完成基础响应式、键盘交互、焦点管理、分页、空态和 55 项 Vitest；尚未完成全页面 DOM/E2E、完整 WCAG 和旧界面最终退役。

1. **功能需求**

   Console 应为企业管理员提供稳定、一致、可访问的运营体验，关键操作具备预检、影响范围、进度、撤销/补偿、审计入口和错误恢复；核心用户旅程必须由真实浏览器自动化覆盖。

2. **使用场景例子**

   运维人员使用键盘和屏幕阅读器定位失败的跨存储修复，查看影响文档，执行单项重试并收到结果播报；浏览器刷新后筛选、分页和任务上下文仍可恢复。

3. **功能作用**

   减少误操作和培训成本；保证不同能力用户可使用；防止后端契约已完善而界面仍因状态遗漏、重复入口或无反馈导致运营失败。

4. **功能实现**

   - 建立统一设计 token、状态/错误词汇、危险操作确认、异步任务反馈、通知中心和 URL 可恢复筛选状态。
   - 为登录、租户、KB、Workflow、审批、Run、Provider、修复、备份/告警形成 Playwright 浏览器 E2E；对组件补 DOM 与无障碍断言。
   - 执行 WCAG 2.2 AA 自动扫描和人工键盘/读屏/对比度检查；桌面、平板、窄屏均纳入回归。
   - 维护旧 Debug/Legacy 页面 owner 与关闭清单，统一 Console 达到功能等价后删除重复实现；验收要求浏览器 console 零错误及关键失败路径可恢复。

### ENT-16 模块化、供应链安全与可控发布

- 优先级：P2
- 当前状态：已有三平面边界、迁移门禁、锁文件构建和 CI；Execution 等文件仍过大，SDK/package 空壳，尚无完整企业软件供应链和渐进发布闭环。

1. **功能需求**

   系统应支持按领域独立测试和发布、可追溯构建、SBOM、依赖/镜像漏洞治理、制品签名、数据库兼容门禁、灰度发布和自动回滚。

2. **使用场景例子**

   团队只修改 Provider 路由。CI 能识别受影响模块、运行契约和安全检查、生成签名镜像及 SBOM；灰度 5% 流量后发现错误预算消耗过快，自动停止扩容并回滚，而不影响数据库兼容。

3. **功能作用**

   降低巨型模块的回归风险和交付周期；提高漏洞响应、制品可信度和发布可恢复性；支持多团队并行开发。

4. **功能实现**

   - 按 domain router/service/repository/schema 拆分 Execution，稳定 OpenAPI/事件/DSL 契约后再提取共享 SDK，禁止循环依赖。
   - CI 生成 CycloneDX/SPDX SBOM，执行 SAST、依赖/容器扫描、许可证策略、secret 扫描和 provenance；制品使用 Sigstore/Cosign 或等价机制签名。
   - 数据库迁移采用 expand/migrate/contract，发布前执行前后版本兼容测试；配置和 feature flag 有 owner、到期时间和审计。
   - 验收覆盖 N-1/N/N+1 兼容、迁移中回滚、签名校验失败、漏洞阻断、灰度指标自动停止和灾难回滚演练。

## 6. 统一完成定义

任何需求不得仅凭“代码存在”标记完成。企业级完成至少同时满足：

- 需求、数据模型、接口/事件契约和权限边界已记录；
- 正常、失败、并发、重试、取消、恢复和跨租户负向测试通过；
- 在与生产等价的多实例或外部联调环境完成真实验证；
- Console、指标、告警、审计、runbook 和清理流程齐全；
- 明确 RPO/RTO/SLO、容量上限、降级行为和责任人；
- 工程文档中的“已完成/未完成”表述与运行证据一致。

本文是需求基线，不代表上述 16 项已经实现。每项进入开发前应拆分对应设计文档、迁移计划、测试矩阵和发布/回滚方案。
