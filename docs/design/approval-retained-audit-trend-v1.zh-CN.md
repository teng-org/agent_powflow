# 审批独立审计事实与趋势 v1

- 状态：已实现并完成数据库、全栈与浏览器验收
- 最近验证：2026-08-03
- 时区：UTC

## 1. 问题与目标

实时审批队列位于 `run_approvals`，并通过 `run_id` 级联依附 Run。删除已结束会话时，队列记录会被正常清理，但这也会抹掉历史处理量、超时率和处理时长，导致运营趋势无法作为可靠审计证据。

本设计把“当前可处理状态”和“已发生事实”分开：

- `run_approvals` 继续承担实时待办、决定幂等和 checkpoint 恢复；
- `approval_audit_facts` 无 Run 外键，承担独立保留的创建与终态事实；
- 两表由 `RunApprovalService` 在同一事务同步，任一写入失败都会整体回滚。

## 2. 数据与迁移

Flyway V7 创建并回填 `approval_audit_facts`，字段包含审批、租户和原 Run 标识、指派角色、状态、决定、是否超时、创建/终态时间和处理时长；既有取消记录以 `updated_at` 作为可用的终态时间。表只保留运营聚合所需字段，不复制 checkpoint、说明或决定原因等敏感正文。

新建、决定、自动超时和取消均在业务事务内同步审计事实；后续删除 Run 不影响该表。迁移执行后保持 checksum 不变，后续数据修正必须通过新版本向前演进。

## 3. 查询与权限

`GET /api/v1/approvals/trend?days=30` 支持 1–90 天窗口，固定返回完整 UTC 日期序列，包括零数据日期。每个日期返回：

- 新建、已决定、同意、拒绝、超时和取消数量；
- 当日已决定审批的平均处理秒数。

趋势查询与实时列表/SLA 摘要使用相同的 tenant 和 `assignee_roles` 数据库侧过滤；平台管理员可查看本租户全部事实。多角色审批只保留一条事实，因此不会因角色展开而重复计数。

## 4. Console

审批台提供 7/14/30/90 天选择、创建/决定双柱、超时标记和窗口汇总。该运营图表属于高频信息面，不使用入场或柱形动画。桌面布局无页面溢出；390px 窄屏将日期列约束在卡片内部横向滚动，不裁切整页内容。

## 6. 后续边界

当前完成的是可查询的运营事实，不是法规级冷归档。仍需结合明确的组织留存期限补归档/删除策略、对象存储不可变归档、导出签名，以及把超时/逾期信号接入外部 Alertmanager 或 Webhook。
