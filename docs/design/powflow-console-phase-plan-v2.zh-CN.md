# Powflow Console 阶段性计划 v2（IA 重构 + 登录分离 + 接口目录驱动）

- 版本：v2
- 日期：2026-03-04
- 状态：Planned
- 关联：
  - `docs/decisions/ADR-011-debug-web-full-migration-to-console-ia.zh-CN.md`
  - `docs/design/powflow-console-implementation-checklist-v1.zh-CN.md`

## 1. 目标与范围
本阶段目标是把当前 Console 从“功能堆叠”升级为“层级清晰、交互稳定、可扩展”的控制台结构。

核心范围：

1. IA 重构：顶栏一级导航 + 左栏二级导航 + 右侧内容容器。
2. 登录分离：移除业务页内双登录卡，改为独立控制台登录页。
3. 菜单细分：引入子标题（section）与折叠/定位/高亮联动。
4. 调试升级：从“手填请求”升级为“接口目录驱动模板填充”。

非目标（本阶段不做）：

1. 租户控制台独立部署与权限体系完整化（先预留）。
2. 前端全量视觉重设计（先结构稳定，再统一视觉）。
3. 新增大批后端接口（优先复用已有接口）。

## 2. 目标 IA（信息架构）
### 2.1 一级导航（顶栏固定）
1. 仪表盘
2. 智能体
3. 租户管理
4. 系统配置

### 2.2 二级导航（左栏固定，随一级切换）
每个一级域维护独立菜单树：`menu -> sections`。

### 2.3 内容区（右侧容器内滚动）
1. 左上角固定显示当前子菜单标题。
2. 内容由多个 section 组成，支持折叠/展开。
3. 点击左栏 section 自动滚动定位。
4. 滚动过程中 section 可见性驱动左栏高亮。

## 4. 分阶段施工计划
### P1：壳层与导航重构（先做）
目标：先把页面结构稳定下来，不改核心业务逻辑。

任务：

1. 新建 `ConsoleShell`（TopNav + SideNav + ContentHost）。
2. 重构导航状态模型：
   - `activePrimary`
   - `activeMenu`
   - `activeSection`
   - `expandedSections`
3. 页面改造为 section 化内容块（统一锚点）。
4. 实现滚动定位与高亮联动（`IntersectionObserver`）。
5. 右侧内容区居中 + 容器内滚动，顶栏/左栏固定。

验收：

1. 一级切换、二级切换、section 定位联动正常。
2. 刷新页面后菜单状态可恢复（本地持久化）。
3. 现有功能可用，不出现功能回归。

### P2：登录页分离
目标：控制台作为全局管理系统，登录与业务页面解耦。

任务：

1. 新建 `ConsoleLoginPage`。
2. 业务页移除 `Control Plane 登录`、`Execution 登录`卡片。
3. 统一 token 存储、续期、失效跳转。
4. 控制台 header 显示管理员信息和退出入口。

验收：

1. 未登录无法进入控制台业务页。
2. 登录成功后自动加载首页与默认菜单。
3. token 失效时自动跳回登录页并给出明确提示。

### P3：菜单细分与交互增强
目标：提升可用性与信息密度管理。

任务：

1. 子标题折叠/展开与默认展开策略。
2. “当前位置”高亮（一级/二级/section 三层）。
3. 统一右侧详情区（可复用 detail panel/drawer）。
4. 统一筛选栏样式、分页、空态、错误态。

验收：

1. 不同菜单页交互风格一致。
2. 长页面可通过左栏 section 快速跳转。
3. 无布局抖动，无元素遮挡。

### P4：接口目录驱动调试台
目标：替代手填，提升调试效率和准确性。

任务：

1. 接口目录模型：
   - `group`
   - `endpoint_id`
   - `method`
   - `path`
   - `query schema`
   - `body schema`
   - `example`
2. 接口点选自动填充请求模板。
3. 表单化参数编辑 + 高级 JSON 模式。
4. 请求记录与导出。

验收：

1. 点选目录可自动构建请求。
2. 常用接口不再需要手动拼路径和 body。
3. 可回放最近请求。

## 5. 技术设计约束
1. 保持现有 composable 结构可复用，避免一次性重写。
2. 页面拆分优先：容器层（布局）与业务层（接口调用）分离。
3. 新增交互能力优先前端落地，不阻塞后端。
4. 全程保留 build/test 可运行状态。

## 6. 风险与应对
1. 风险：重构期间页面逻辑回归。
   - 应对：分阶段迁移，每阶段 build + test + smoke 验证。
2. 风险：菜单树复杂导致状态混乱。
   - 应对：统一导航状态模型，单一数据源管理。
3. 风险：目录驱动 schema 不完整。
   - 应对：先覆盖高频接口，低频接口走高级模式兜底。

## 7. 里程碑与交付物
1. M1（P1 完成）：新壳层与四域导航上线。
2. M2（P2 完成）：独立登录页上线，业务页清理登录卡。
3. M3（P3 完成）：section 联动、折叠、高亮和统一交互完成。
4. M4（P4 完成）：接口目录驱动调试台上线。

交付物：

1. 代码：`apps/web-admin` 壳层与页面重构。
2. 文档：本计划 + 对应 ADR 更新（必要时）。
3. 验收记录：每阶段功能清单与截图。

## 8. 当前执行建议
从 P1 开始，先做结构，不改业务调用：

1. 先把四个一级导航和左侧菜单树挂好。
2. 把现有页面“搬家”到对应一级域，不改接口逻辑。
3. 最后再加 section 锚点与滚动联动。
